# 보이스닥터 블로그 자동 생성 시스템

네이버 블로그 `blog.naver.com/voicedr` 원고를 **월·화에 각 5편씩(주 10편)**
자동 생성합니다. 사장님이 그중 골라서 발행하십니다.

발행량을 늘리는 것이 목적이 아닙니다. **고를 이유가 생기도록 다섯 편의
성격을 뚜렷이 다르게** 만드는 것이 목적입니다.

## 발행 주기

| 요일 | 월 | 화 | 수 | 목 | 금 | 토 | 일 |
|---|---|---|---|---|---|---|---|
| 원고 | **5편** | **5편** | — | — | — | — | — |

Routine cron `57 21 * * 0,1` (UTC) = 한국시간 월·화 06:57

## 하루의 흐름

```
월·화 06:57 KST  Routine 자동 실행 (클라우드, PC 안 켜도 됨)
   │
   ├─ brand/ 에서 필자 프로파일·가드레일·H섹션 로드
   ├─ keywords/queue.tsv 에서 슬롯 A~E 로 키워드 5개 pick
   │    A 직업군 · B 발음 · C 증상 · D 방법 · E 탐색
   ├─ 원고 5편 생성 (1,600~1,900자, 제목 후보 6개씩)
   ├─ wrap_lines.py 로 줄바꿈 양식 적용 (한 줄 24자 이하)
   ├─ 검사 4종 통과할 때까지 수정
   ├─ drafts/YYYY-MM-DD/ 커밋 + used.tsv 갱신
   └─ 웹페이지(아티팩트) 같은 URL 갱신 → 알림 도착

아침에 링크 열기 → 5편 중 고르기 → [제목 복사] [본문 복사]
                → 네이버 붙여넣기 → 예약발행
```

## 검사 4종

| 스크립트 | 무엇을 막나 |
|---|---|
| `check_similarity.py` | 유사문서. 기존 글·당일 다른 4편과 연속 15자 일치 금지 |
| `check_titles.py` | 제목 구조·유형·금지어 (H22) |
| `check_voice.py` | H섹션 확정 규칙이 실제로 들어갔는지 |
| `wrap_lines.py --check` | 한 줄 24자 이하 |

`check_voice.py` 는 **문서에만 적히고 지켜지지 않던 규칙**을 잡으려고
만들었습니다. 2026-09-16 원고 5편이 전부 `여러분` 0회, `운영` 1회였는데
전부 H섹션에 적혀 있던 규칙이었습니다.

## 폴더 설명

| 경로 | 용도 | 누가 채우나 |
|---|---|---|
| `brand/author-profile.md` | **최상위 기준.** "이 사람이라면 이 표현을 쓸까" | Claude가 발행본에서 추출 |
| `brand/tone-and-manner.md` | H섹션(발행본에서 배운 규칙) + A~F 실측 | Claude가 자동 갱신 |
| `brand/guardrails.md` | 유사문서·비의료·표시광고법 | Claude + 사장님 검토 |
| `brand/profile.md` | 브랜드 기본정보, CTA 방침 | **사장님** |
| `corpus/` | 기존 상위노출 글 원본 4편 | **사장님** (완료) |
| `revisions/` | **사장님이 고쳐 발행한 원고.** 가장 정확한 피드백 | **사장님** (붙여넣기) |
| `keywords/POLICY.md` | 키워드 선정 기준·경쟁도 상한·구글 경로 | Claude |
| `keywords/seed.md` | 씨앗 키워드 | **사장님** (완료) |
| `keywords/raw/` | 검색광고 키워드도구 xlsx 원본 | **사장님** |
| `keywords/inflow/` | 블로그 유입분석 xlsx + 분석 리포트 | **사장님** |
| `keywords/queue.tsv` | 검색량·유입 근거가 붙은 키워드 큐 | 스크립트가 생성 |
| `keywords/used.tsv` | 소진 이력 (중복 방지의 원본) | 시스템이 자동 기록 |
| `drafts/` | 날짜별 완성 원고 | 시스템이 자동 생성 |
| `delivery/` | 아티팩트 URL, 생성된 페이지 | 시스템 |

## 학습 루프

```
초안 생성 → 사장님이 고쳐 발행 → revisions/ 에 원문 그대로 저장
   → compare_revision.py 로 차이 추출 → H섹션에 규칙화
```

**최신 발행본을 따라 매번 기준을 옮기지 않습니다.** 그러면 기준점이
사라지고 이동 평균만 남습니다.

| 종류 | 확정에 필요한 표본 |
|---|---|
| 문구 (인사말·CTA) | 1편 |
| 구조·스타일 | **3편 전부에서 나타날 때만** |

2편만 보고 확정했다가 두 번 틀렸습니다 (H12·H13). 그래서 기준을
만장일치로 올렸습니다.

## 사장님이 해주실 것

1. **발행하신 글 전문을 붙여넣어 주세요.** 네이버가 이 환경에서 차단돼 있어
   URL로는 제가 못 엽니다. 제목도 함께 주시면 제목 규칙에 반영됩니다
2. **검색광고 키워드도구 파일**을 가끔 주세요 (`keywords/seed.md` 3번 참고).
   xlsx 그대로 주시면 됩니다

## 알려진 제약

- **네이버 도메인 전체가 CONNECT 403** 입니다. 상위노출 문서를 직접 확인할 수
  없어 corpus와 프로파일 기준으로만 씁니다. 매 실행마다 다시 확인합니다
- 구글 트렌드·키워드 플래너도 차단돼 있습니다. 다만 **웹 검색은 됩니다** —
  후보 표현 발굴에 쓰고, 검증은 네이버 검색량으로 합니다
